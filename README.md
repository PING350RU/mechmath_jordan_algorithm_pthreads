# Метод Жордана с выбором главного элемента по столбцу (pthreads)

Параллельная реализация метода Жордана на C++ с использованием POSIX-потоков (`pthreads`).

Это продолжение последовательной версии программы. Сам алгоритм обращения матрицы не изменился, но теперь часть вычислений можно выполнять одновременно на нескольких потоках.

## Идея алгоритма

Как и раньше, работаем с двумя матрицами: исходной \(A\) и единичной \(E\). Последовательно преобразуем \(A\) в единичную матрицу, выполняя те же операции над \(E\). В результате получаем обратную матрицу \(A^{-1}\).

На каждом шаге главный поток выбирает максимальный по модулю элемент текущего столбца, переставляет строки и нормирует ведущую строку.

После этого нужно занулить остальные элементы столбца. Именно эту часть мы распараллеливаем.

Каждый вычислительный поток получает свои строки и независимо преобразует их. Когда все потоки заканчивают работу, алгоритм переходит к следующему столбцу.

Таким образом, порядок шагов метода сохраняется, а наиболее трудоёмкая часть вычислений выполняется параллельно.

## Структура проекта

- `main.cpp`: обработка аргументов, вывод результатов, время и невязка.
- `matrix.cpp`: генерация матрицы по формулам или чтение из файла.
- `jordan.cpp`: метод Жордана и работа с pthreads.
- `functions.h`: объявления функций.
- `CMakeLists.txt`: сборка проекта с поддержкой потоков.
- `sample.txt`, `swap.txt`, `singular.txt`: небольшие тестовые матрицы.

## Параметры запуска

Программа принимает аргументы командной строки:

`jordan n m k threads [filename]`

- `n`: размер квадратной матрицы.
- `m`: максимальное число выводимых строк и столбцов.
- `k`: номер формулы от 1 до 4, либо 0 для чтения из файла.
- `threads`: количество вычислительных потоков.
- `filename`: путь к файлу, обязательный при `k=0`.

Например, для матрицы размером 2000 × 2000 можно использовать 1, 2 или 4 потока.

При `threads=1` вычисления выполняются последовательно, без создания дополнительных потоков.

## Как работает распараллеливание

Потоки создаются один раз и используются на протяжении всего обращения матрицы.

Строки распределяются циклически. Например, при четырёх потоках первый обрабатывает строки 0, 4, 8 и так далее, второй строки 1, 5, 9, третий строки 2, 6, 10, четвёртый строки 3, 7, 11.

Ведущая строка пропускается, поскольку её уже обработал главный поток.

Для синхронизации используются `pthread_mutex_t` и `pthread_cond_t`. Они позволяют дождаться завершения текущего шага, прежде чем переходить к следующему столбцу.

Это важно, потому что каждый новый шаг должен работать с уже преобразованной матрицей.

## Сборка

### Linux

В том числе на университетском компьютере с CMake 3.14:

```bash
cmake -S . -B build-pthreads -G "Unix Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build-pthreads
```

Запуск:

```bash
./build-pthreads/jordan 2000 6 1 4
```

### macOS (Xcode)

```bash
cmake -S . -B build-pthreads -G Xcode
cmake --build build-pthreads --config Release
```

Запуск:

```bash
./build-pthreads/Release/jordan 2000 6 1 4
```

### Windows (PowerShell, MSYS2 MinGW)

```powershell
cmake -S . -B build-pthreads -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build-pthreads
```

Запуск:

```powershell
.\build-pthreads\jordan.exe 2000 6 1 4
```

Для Windows требуется компилятор с поддержкой pthreads.

Если папка `build-pthreads` уже использовалась с другим генератором CMake, её нужно удалить перед повторной настройкой.

## Проверка результата

Программа выводит исходную матрицу, найденную обратную матрицу, невязку, время обращения и количество потоков.

Для оценки точности используется норма Фробениуса:

\[
\|AA^{-1}-E\|_F.
\]

Время `Time` измеряется только для алгоритма обращения, включая создание и синхронизацию потоков. Генерация матрицы, печать и вычисление невязки в него не входят.

При этом сам метод по-прежнему имеет вычислительную сложность \(O(n^3)\). Распараллеливание не меняет алгоритм, но позволяет сократить время его выполнения.

## Сравнение производительности

Для сравнения запустим одну и ту же матрицу с разным количеством потоков.

На Linux:

```bash
./build-pthreads/jordan 2000 6 1 1
./build-pthreads/jordan 2000 6 1 2
./build-pthreads/jordan 2000 6 1 4
```

На macOS путь к программе будет `./build-pthreads/Release/jordan`.

Сравниваем значение `Time` и вычисляем ускорение:

\[
S_p=\frac{T_1}{T_p},
\]

где \(T_1\) обозначает время работы с одним потоком, а \(T_p\) время работы с \(p\) потоками.

Для больших матриц ускорение обычно заметнее, поскольку затраты на синхронизацию становятся относительно меньше. Конкретный результат зависит от процессора и размера матрицы.

Для тестирования удобно использовать `k=1` и `n >= 1000`.

При `k=4` генерируется матрица Гильберта. Она плохо обусловлена, поэтому на больших размерностях возможны значительные ошибки округления или сообщение о численной вырожденности.
